# 记忆助理

用关键词从过去的对话里定位一条记忆，回原文，找不到就问。

## 命令怎么跑（先看这段）

下面统一写 `mem`。市场安装的插件**不保证 `mem` 在 PATH 里**，所以：

1. 先试 `mem recall ...`；
2. 报 `command not found` / `无法将"mem"项识别` → 换成
   ```bash
   node "$DSH_PROFILE_DIR/node_modules/dsh-memory-assistant/bin/mem.js" recall ...
   ```
   （PowerShell 写 `node "$env:DSH_PROFILE_DIR\node_modules\dsh-memory-assistant\bin\mem.js"`）
3. 连 `DSH_PROFILE_DIR` 都没有 → 说明不是 profile 启动的宿主，直接告诉用户去设置页操作。

## 第一次用：先看有没有导入过

```bash
mem import status
```

- `imported: false` → **别自己动手抽卡**。只说一句，把选择权交给用户：
  > 记忆还没导入。打开「设置 → 记忆助理」，选「只整理当前对话」或「整理全部对话」，插件会自己跑（当前对话几分钟，全部十几分钟），你可以先聊别的。

  然后这一轮按「没有记忆」处理：只答当前上下文里有的，不编过去。
- `pending` 非空（整理停了）→ 让用户在同一张卡片上点「继续」，别自己重跑。
- 全部 `done` → 正常用。

整理是**插件自己做**的：导出 → 切段 → 分批 → 调模型抽卡 → 逐批校验入库，每批落盘、可暂停续跑。它读的是会话文件（只读），不改动任何对话。

### 手工兜底（只在页面接口不可用时）

```bash
mem import start --size 8          # 导出 + 切段 + 分批，打印 batch_dir 与 next
mem import merge --batch 1 --cards <抽好的卡.json>   # 校验入库并记进度
mem import status                  # 看进度，pending 里最小的那批继续
```

## 库会变旧：定期更新

用户说「把最近的也记一下 / 更新记忆」时，让他去 **设置 → 记忆助理** 点「更新记忆（只导新对话）」。

- 只处理**上次入库之后的新消息**（按每场会话的入库时刻判断），不会重跑整个库
- 没有新内容会直接说「没有新的对话内容」，不报错
- 每批入库成功就把那场会话的时刻往后推，中途停了也不会重复

## 按会话查

```bash
mem sessions                          # 哪几场对话进了库：卡数 / 时间跨度 / 标题
mem recall "五层标签 为什么 失败" --session session-2640fd0e-...   # 只在这一场里找
```


## 什么时候用

- 用户提到**过去**：「当初」「上次」「之前那个」
- 用户要**具体事实**：日期、数字、原话、谁说的
- 用户要**引用旧决定**：「我们之前定的是……」
- 进入**有积累的领域**（投资、法务、写作）

**不要用**：答案已在当前对话里；纯创作；一次推理就能得出。

## 怎么查

```bash
mem recall "公告板是怎么丢的" --top 3
```

1. 先从用户这句话里**压出 2–3 个关键词**（对象 + 动作），别用整句
2. 用压出的词查（可选 `--concepts` 指定概念码、`--entities` 指定实体）
3. 先看返回的**状态行**（`【精确命中】/【无精确命中】/【没有】`），再看**标题 + 一句话 + 三行大纲**
4. 精确命中 → 按 `→ 路径 / 章节` 回原文取那一节，直接答，带出处
5. 无精确命中 → **先说没找到什么**（状态行会写「缺哪个词」），再把「提到 X 的有这几件」摆出来
6. 没有 → 空手问：「你记得大概是什么时候、跟谁有关吗？」

## 三态输出（recall 自己判，别自己改口径）

`recall` 的第一行就是状态，`--json` 里是 `state` 字段：

| 状态 | 含义 | 怎么做 |
|---|---|---|
| `exact`【精确命中】 | 问句里的名词都在同一张卡的标题/关键词/引用里出现（缺一个稀有词就不算） | 回原文，直接答，带出处 |
| `related`【无精确命中】 | 没有卡讲到同一件事，但有几张沾到其中一两个词（状态行会写缺哪个） | 明说「没找到 X，但提到 Y 的有这几件」，再按追问协议问一句 |
| `none`【没有】 | 问句里的名词库里一个都没出现过 | 空手反问，别硬答，别拿相近话题凑 |

- 判「精确」**不看分数**：分数会被概念码抬高；`state` 是字面判的
- 输出里出现「（并列：拿不准就问）」时，摆 2–3 条让用户认：「是 A 还是 B？」
- 状态行里的「覆盖 %」只是证据强度，不要念给用户听
- 输出里出现「⚠ 你问的是否定」时：**别把这张卡当成「没发生过」的证据**。
  库里通常只记「做过」的事，没有「没做过」的记录。正确说法是
  「我这边只记到『做过』的记录，没记到『没做』」——然后请用户确认，不要替他把话说完。

## 主动提（插件会自己打招呼）

如果上下文里出现一段以 `[记忆提示 · 可能相关]` 开头的卡片，那是插件按**这一轮的话题**自己挑的（最多 3 条；被预算挤掉的会写「另外还有 N 条」）。

- 用得上就接一句「这事以前定过……」，并给出处；**用不上就别提它**，不要为了用而硬扯
- 它只是候选，不是已确认事实；要下结论仍回原文核对
- 用户说「展开」→ 按卡上的 `u` 回原文取那一段

## 反馈（这是插件唯一的"成绩单"）

回答完，**必须**记一条：

```bash
mem feedback --key <卡片key> --verdict good      # 用户认可
mem feedback --key <卡片key> --verdict partial   # 沾边但不准
mem feedback --key <卡片key> --verdict bad       # 找错了
```

用户没有明确表态时，按下一轮的行为判断：继续追问同一件事 → `partial`；换话题 → `good`；纠正你 → `bad`。

如果输出里有「注：本轮日志没写进 …（沙箱只读），检索结果照常」——**这不是错误**，检索和答案都有效，只是这一条没记进统计，继续照常回答即可。

## 看统计

```bash
mem stats
```

输出：卡片数、查询次数、需追问率、满意度（good=1、partial=0.5、bad=0）。

## 纪律

- **不猜**：找不到就是找不到
- **不编**：答案必须能指回某一段原文
- **不改词**：检索用的词来自用户原话，别自己换同义词（同义归并在写入端）
- **一次只查一个对象**：一句话里有两个问题时，分开查

## 参与带轮次戳的共享讨论时（纪律）

如果共享记忆里的讨论文档带「轮次戳」（`[轮次 N · 待 …]`），**你每写一轮，必须在回复里直接说出下面这一行**：

```
现在该谁：<链名>（轮次 N）→ <待谁>
```

理由：主人按这一行决定去激活谁；漏说一次，他就会激活错人。

**续写时三件事一次做完，缺一不可**：

1. 推进轮次戳
2. 更新该链顶部「当前待回」段（链上看的和地方看的必须是同一份）
3. 同步信号板（如有 `board --fix` 之类命令就跑一次）

**不要只在正文里写「等你回」**——正文不等于状态。状态要写在戳和摘要段里，否则下一次没人找得到。
